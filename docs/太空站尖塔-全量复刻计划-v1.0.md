# 《阿卡姆号》· 全量复刻杀戮尖塔 —— 总体计划 v1.0

> 目标：把现有的「战斗原型」扩展成**完整的杀戮尖塔式循环**（主题＝太空站/克苏鲁，
> 骨架＝尖塔：地图 → 战斗 → 奖励 → 商店/休整/事件 → 精英 → BOSS），
> 并把视觉推到「像素惊艳」级。
>
> 本计划的边界＝策划案 v2.1 锁定的 **Stage 1**：开场 + 教程 + 核心区 + 第一层（15 层节点）+ 第一个 BOSS。
> 第二/三幕、多角色、飞升难度 **不在本计划内**。
>
> 原创机制（回声连击、隔离值、神印、血肉重塑）是本作的身份，**原样保留**，叠加在尖塔骨架上。
> 复刻的是尖塔的**结构与循环**，不是它的皮肤。

## 0. 对外部建议的裁定（先回答「根据这个你有什么推荐」）

| 提议 | 裁定 | 说明 |
|---|---|---|
| 瓦片 32×32 | ✅ **采纳** | 用于战斗地面层 + 核心区步行层（提示词已就绪：`素材提示词-空间站地砖集.md`）。注意：尖塔本体地图是**节点分支图**，不是走格子——见 §2 |
| 角色 32×48 | ✅ **采纳并升级为全角色统一规格** | 顺手解决交接文档 P1 的像素密度不一致（当前 7.0 / 9.0 / 3.5 三套密度并存） |
| 卡牌 128×192 + 64×96 插图区 | ✅ **采纳（竖版卡）** | 显示 2×＝256×384。插图区里的角色（32×48 的 2 倍）与战场角色**屏上同尺寸**，像素密度全站统一 |
| 窗口 1280×720 + 内部 640×360 viewport 拉伸 | ❌ **不采纳，改为 1920×1080 + 虚拟像素网格** | 理由见下，这是本计划最重要的一个技术裁定 |
| 手牌一行 4~5 张 | ⚠️ 修正 | 上限按尖塔标准 **10 张**；1~10 张的手牌版式查表已实现（`combat_view._layout_hand`），只随卡牌尺寸微调 |
| Filter=Nearest、Mipmaps 关 | ✅ 已是现状 | `project.godot` 已设 `default_texture_filter=0`（Nearest 全局默认），2D 默认无 mipmap |
| 角色/卡牌 PackedScene 预制体 | ✅ 已是硬约束 | `项目规则-预制体规范.md`：禁止运行时 new 节点，全部走 PackedScene |
| 碰撞盒只放脚部（高 16px） | ✅ 采纳 | 核心区步行层使用 |

### 为什么不切换到 640×360 内部分辨率

1. **已完成的交互层会全部作废。** 尖塔2 级的出牌交互（点击拾起、拖拽阈值、19 段箭头、准星、出牌队列）
   是 1940 行 `combat_view.gd` + 6 套测试、几十个手调像素常量，全部按 1920×1080 调出来的。
   换 640×360 等于把这部分已付代价的工作重新调一遍。
2. **尖塔是文字密集型 UI。** 卡牌描述、遗物 tooltip、事件正文、商店标价——在 640×360 里要放得下这些字，
   字号得压到 8px 以下，可读性崩塌。原版尖塔自己也是「高清 UI + 高清文字」。
3. **项目已经有一套等价且更好的方案：** `pixel_frame.gd` 把所有像素 UI 标准化在 **4×4 屏幕像素网格**上，
   等价于一张 480×270 的虚拟像素画布以 4× 渲染——像素纯净度和「640×360×2」完全一样，
   还额外保留了一层高清文字。

**采纳提议中真正值钱的部分（美术资产的规格），用 4× 而不是 2× 来落地：**

| 资产 | 美术像素 | 屏幕像素 | 倍率 |
|---|---|---|---|
| 人形角色（沈明砚 / 眷族杂兵） | 32×48 | 128×192 | ×4 |
| 宋梅（设计上就矮） | 32×40 | 128×160 | ×4 |
| 精英·眷族宿主 | 48×64 | 192×256 | ×4 |
| BOSS·眷族祭司 | 96×128 | 384×512 | ×4 |
| 地砖 | 32×32 | 128×128 | ×4 |
| 卡牌（整张） | 128×192 | 256×384 | ×2（卡牌层） |
| 卡内插图 | 64×96 | 128×192 | 卡内 ×2 |
| 遗物 / 注剂图标 | 16×16 | 64×64 | ×4 |
| 状态 / 意图图标 | 12×12 | 48×48 | ×4 |

> 铁律：**任何资产在屏幕上必须以整数倍显示**——世界层统一 ×4，卡牌层统一 ×2。
> 这就是「2 倍缩放保证像素对齐」想要的效果，而且整站只有两档倍率，不会糊。

## 1. 像素管线总纲（视觉一致性的根）

### 1.1 虚拟网格

- 全局虚拟分辨率 **480×270**（1920÷4 × 1080÷4），所有像素美术按此网格绘制与摆放；
- 新增一个 `PixelGrid` 静态工具：常量 `CELL=4`、`snap(Vector2)`、`rect(Rect2)`，
  世界层精灵的 `position/scale` 一律过 snap；
- 文字例外：像素字体（`pixel_font_theme.tres`）按屏幕原生分辨率渲染，**字号取 4 的倍数**对齐网格；
- 窗口策略：**默认无边框全屏**（1080p 屏＝真 1:1，零采样损失）；窗口模式维持现状
  （stretch disabled + 代码级安全画布适配，见交接文档 7.5/7.6 与 `战斗UI-2.5D版式与素材规范.md` 的 1055 安全区）。

### 1.2 卡牌版式 128×192（竖版）

```
┌────────────────────┐ 0
│ ●13  名字条         │ 0–20   左上费用宝石 16×16（悬出卡外，尖塔式）
├────────────────────┤ 20
│                    │
│      插图区         │ 20–116  64×96，水平居中（32×48 角色的 2 倍）
│                    │
├────────────────────┤ 116
│  类型条（攻击/技能/能力）│ 116–128
├────────────────────┤ 128
│  描述区             │ 128–176  关键数字用归属色高亮
├────────────────────┤ 176
│  归属条（规程/异化/中立）│ 176–192  归属识别色（美术基调 §2）
└────────────────────┘ 192
```

- 卡框 ×4（规程/异化/中立/升级金），生成提示词复用 `素材提示词-牌框九宫格.md`，按 128×192 重排；
- 升级卡＝金框 + 描述区数字变 `#FFE08C`（色板「升级」行）；
- **UI 永远是工程系冷青**，即使卡面是异化系（美术基调 §5 交界规则）。

## 3. 里程碑

> 沿用项目铁律：每个里程碑**独立可跑、可验收**；美术资产先过制作人复核（美术基调 §7）再接入；
> 每个里程碑收尾跑 `--import` → 六套测试 → 截图存 `artifacts/verification/`。

### M0 像素地基（管线统一）

**目标**：全站只有一套像素密度，卡牌换装 128×192，地砖上墙。

- 新增 `src/ui/pixel_grid.gd`（常量 + snap 工具），世界层站位与精灵尺寸过网格；
- 卡框重制 128×192 ×4 归属；`battle_card.gd` 换新框、`CARD_SIZE` → 256×384、插图区接 `CardArt`；
- `hand_tray` 1~10 张版式表随卡尺寸微调（手牌态可 ×0.85，悬停全尺寸）；
- 角色规格统一：沈 32×48、宋 32×40（按 RikaAI 规范重生成序列帧 + 去底 + 并集包围盒实测流程）；
- 地砖集 32 格生成、切片、3×3 平铺校验，接入战斗地面层（背景之下、角色之下）。

**验收**：三个角色屏上密度全部 =4.0；卡内插图与战场小人一样大且零采样模糊；地砖拼接无接缝暗线；六套测试全绿。

### M1 战斗系统补全

**目标**：战斗规则面追平尖塔第一幕。

- 卡牌升级：`card_instance` 加升级态，奖励/医疗舱入口，金框显示；
- 牌型补全：能力牌（战场持续态图标行）、状态牌、诅咒牌「记忆碎片」（打出无收益、塞牌堆，神印事件的载体）；
- 抽/弃/消耗堆查看（战斗内点开数字弹层，消耗已有 `exhaust_ash` 特效直接复用）；
- 状态图标 + tooltip（12×12 图标 ×4，`pixel_frame` 网格绘制）；
- 敌人意图扩展：攻击/防御/强化/削弱/多段/未知；AI 按模式表驱动；
- 内容量：卡池 19 → 40+（含全部升级版），敌人 2 → 6+，含精英**眷族·宿主**；
- `damage_pipeline` 不动签名，只扩状态词表。

**验收**：升级金卡、能力图标、记忆碎片塞牌、宿主战可打；`test_combat` 扩容后全绿。

### M2 运行骨架（关键路径）

**目标**：尖塔的脊柱——一局游戏的完整状态与推进。

- 新增 `src/core/run.gd`（纯逻辑，可测）：生命/器官/牌组/遗物/注剂/地图进度/seed；
- **地图**：15 层分支节点图（战斗×N、异常讯号、医疗舱、补给舱、宝箱、精英、BOSS），
  生成算法对齐尖塔（每层 2~4 节点、跨层连接规则、不可交叉）；
- 地图 UI：**阿卡姆号甲板剖面蓝图**——工程系冷青线框 + 舱室图标节点 + 已走路径流光
  （结构 100% 尖塔，皮是太空站剖面图，这是视觉差异化的第一张牌）；
- 战斗结算 → **奖励页**：器官 + 三选一卡（`reward_pool` 已有）+ 跳过；
- 死亡 → 血肉重塑演出 → 回第一层（无代价，锁定设计）。

**验收**：标题开一局 → 打 3 场拿 3 张卡 → 死亡 → 重塑重来，全链路无断裂；地图生成 100 层无非法连接（脚本断言）。

### M3 舱室节点补全

**目标**：地图上每种房间都可进、可交互。

- 医疗舱：治疗 30% / 删除一张卡（二选一）；
- 补给舱（商店）：器官买卡/遗物/注剂 + 删卡服务，买断制；
- 宝箱舱：开箱得遗物；
- 异常讯号（事件 ×8）：含 2 个神印事件（塞记忆碎片、隔离值选项）——机制即叙事；
- BOSS 舱：眷族·祭司战 + 专属奖励 + 幕间收束演出（Stage 1 收尾）。

**验收**：一条完整通关路线里每种节点至少经过一次；事件选项全部接 `run.gd` 状态。

### M4 构筑深度

**目标**：尖塔构筑感的两大支柱。

- 遗物（暂名**模组**）×20：太空站主题（外骨骼、船员铭牌、泄压阀……），事件钩子用信号接入
  （`combat_manager` 已有信号层，快照驱动 UI 的架构直接复用）；
- 遗物槽 UI（左上角排 + tooltip）；
- 注剂 ×10（战斗内使用、3 槽、商店与掉落来源）。

**验收**：20 遗物各有单测钩子断言；一场带 3 遗物 2 注剂的战斗全流程无回归。

### M5 战斗视觉惊艳层

**目标**：把已有的 juice 体系推到「截图能发宣传图」。

- 灯光情绪 per 舱室：`battle_lighting.tscn` 三灯位按节点类型换色温（战斗冷白 / 精英洋红渗光 / BOSS 只剩自发光）；
- **隔离值畸变 shader**：全屏 post-processing，隔离 6+/8+/10 逐级 UI 歪斜、色相漂移、文字偶发闪烁（策划案 §2.2 锁定表现）；
- BOSS 出场演出：短暂 chromatic aberration + 顿帧 + 雾涌；
- 升级金卡 foil 微闪 shader；命中已有 hit_flash/trauma 保持；
- 舱门转场：战斗↔地图用舱门开合遮罩（工程系）。

**验收**：隔离 0/6/10 三档截图对照；BOSS 出场时序实测 ≤1.2s；帧率 ≥60。

### M6 外壳与收束

**目标**：像个能发的游戏。

- 标题界面：`沈明立绘.png`（1024×1536 已有）+ 感染蔓延 shader + 菜单；
- 新手引导：首战/首地图引导（复用 `thought_bubble`，一次性）；
- 牌组查看器（地图与战斗内）、结算画面（血肉重塑演出 / 通关收束）；
- 音频全接线（34 个 WAV 已有：出牌/命中/购买/开箱/事件/BOSS）；
- Run 存档（`user://` 单槽 + 继续）。

**验收**：从双击 exe 到「打赢祭司 / 血肉重塑」全程不碰调试工具；关闭游戏重开能续局。

### M7 核心区步行枢纽（地砖 + 32×48 小人的主场）

**目标**：策划案 Stage 1 的「核心区」做成可走的小舱——瓦片规格真正落地的地方。

- `TileMapLayer` 舱室 + 32×48 步行角色（脚部碰撞 16px，8 向，4px 网格吸附移动）；
- 交互点：血肉重塑池（死亡回这里）、宋梅 NPC（对话/贸易）、下一层舱门；
- 光照：点光 + 感染角落洋红渗光（复用 lighting 场景套路）。

**验收**：步行手感 4px 对齐无抖动；与 run 循环（死后回核心区）接通。

> 顺序可调：若想先看到「走小人」，M7 可提前到 M3 之后做，不影响关键路径。

## 4. 「惊艳」的来源：统一，不是堆料

本项目视觉的杀手锏已经被美术基调锁定，执行时反复自查：

1. **一套像素密度**（M0 完成后全站只有 ×4 / ×2 两档整数倍率）；
2. **一套 32 色**（色板外颜色＝废稿）；
3. **一条交界规则**（工程系在外、异化系在内；UI 永远冷青）——地图蓝图、卡框、HUD 全部工程系，
   让异化只在「该出现的地方」出现，反差本身就是高级感；
4. **克制的动效**（juice 已有 trauma/顿帧/粒子五配方，新增动效先问「它表达什么机制」）；
5. **留白与暗部**（`#0A0E14` 底 + 少量发光，比满屏特效更贵）。

## 6. 不做 / 风险

**不做**（沿交接文档 §10 锁定）：
- ❌ 3D（纯 2D）；❌ 死亡惩罚；❌ 恢复「血肉争夺」；❌ 动美术基调硬约束；❌ 用 pwsh 直接启动 Godot；❌ eval 里写循环。

**风险与对策**：
- `combat_view.gd` 已 1940 行：M1 起新 UI 一律独立场景（Overlays 层已有分组惯例），禁止继续膨胀单文件；
