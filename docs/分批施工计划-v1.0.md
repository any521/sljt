## 0. 全局边界（每批次开工前必读）

### 0.1 还原度的定义 [锁定]

| 层 | 要求 |
|---|---|
| **布局** | 按原版的**锚点几何**做（§1 实测表），不是「看起来像」 |
| **机制 / 数值 / 流程** | 直接对齐原版：回合结构、能量与抽牌、格挡、状态系数、意图模式、地图生成规则、奖励/商店/休整/事件循环 |
| **卡牌 / 遗物 / 敌人 / 事件内容** | **全部原创**：名称、描述、风味、美术、音效一律自制 |

> 禁止：使用原版的卡名、卡牌描述文案、美术资源、音效、UI 位图。
> 允许：对齐机制与数值；参考原版的**布局尺寸**与**交互时序**。

### 0.2 像素规格 [锁定]（上位计划 §1）

- 虚拟网格 **4×4**：世界层资产 ×4、卡牌层 ×2，任何资产在屏幕上必须是整数倍；
- 卡牌 **128×192 美术 → 屏上 256×384**；卡内插图 **64×96 → 128×192**；
- 角色 **32×48**（宋梅 32×40）；精英 48×64；BOSS 96×128；地砖 32×32；
- 图标：遗物/注剂 16×16、状态与意图 12×12、地图节点 24×24；
- 文字例外：像素字体按屏幕原生分辨率渲染，字号取 4 的倍数。

### 0.3 并行安全（多窗口开工前必须遵守）

1. **只改自己批次的写作用域**。跨域需求写进批次的「依赖」，不要顺手改别人的文件。
2. src/ui/combat_view.gd 已 1940 行，**冻结**：任何批次不得再往里加代码；新 UI 一律独立场景+独立脚本，挂进 Overlays 的既有分组。
3. 下列共享文件必须**串行**，指定唯一负责人：

| 文件 | 负责人 | 说明 |
|---|---|---|
| project.godot | B0 | 显示/输入/autoload 设置 |
| scenes/main.tscn | 集成者（收尾统一装配） | 各批次只提交自己的场景，不自行改 main |
| src/data/card_data.gd（schema） | B1 | schema 变更需广播 |

4. **每批次收尾四件套**（缺一不算完成）：`--import` → 跑本批次测试 → 截图存 artifacts/verification/ → git commit。
5. 提交前缀按批次：B2(card): … / B5(map): … ，便于按批次回滚。
6. **改脚本后先 --import 再 --script**，否则全局类别名表失效会报一堆假错误。

## 3. 批次详述

### B0 · 像素地基与工具
- 目标：把 4×4 虚拟网格变成代码约束，而不是口头约定。
- 产出：PixelGrid（CELL=4、snap(Vector2)、snap_rect(Rect2)、to_art(Vector2)）；确认 project.godot 默认最近邻；把 §0.2 落成 docs/美术资产规格表.md。
- 验收：单测断言 snap() 对任意输入都落在 4 的倍数上；截图无半像素模糊。
- 不要做：不要改任何已有 UI 坐标。

### B1 · 数据 schema 与数值对齐表
- 目标：让「90% 还原」变成**填表**而不是写代码。
- 产出：① schema（卡：id/费用/类型/稀有度/派系/效果数组/升级差异；遗物；注剂；敌人：血量区间/意图模式表/掉落；事件）；② docs/数值对齐表.md（原版数值 → 本项目数值逐条对照：能量≈6 伤害、格挡≈0.9、抽 1 牌≈3、受伤 +50%、输出 −25% 等）；③ tests/test_data_schema.gd（字段完整性、稀有度分布、费用曲线断言）。
- 验收：schema 测试全绿；对齐表覆盖所有可量化项。

### B2 · 卡牌渲染重制（128×192 美术）
- 目标：卡牌换成 §0.2 规格竖版卡，像素密度与全站统一。
- 产出：battle_card.tscn 按版式重排（名字条 0–40 / 插图 40–232 / 类型 232–256 / 描述 256–352 / 归属 352–384，费用宝石悬出左上）；卡框改九宫格素材（素材提示词-牌框九宫格.md 改尺寸）；描述关键数字用归属色高亮。
- 验收：截图逐项对照版式表；断言卡尺寸 256×384 且 scale 为整数倍。
- 不要做：不要动 combat_view.gd（手牌定位属 B3）。

### B3 · 手牌/托槽/箭头重定标（**必须串行**）
- 目标：卡牌变大后重新标定已调好的交互常量。
- 产出：1~10 张新版式表（沿用现有联立求解：整排不出框 + 相邻不遮挡）；托槽最小宽度与弧形重测；箭头几何按新卡宽微调。
- 验收：verify_hand_layout.gd 全绿；verify_card_interaction.gd 全绿。
- 风险：唯一碰 combat_view.gd 的批次，**独占该文件**。

### B4 · HUD 按原版锚点重排
- 目标：按 §1 锚点表重排战斗 HUD。
- 产出：顶栏、乘员面板、能量球（距左 100/距底 252）、结束回合（距右 96/距底 144，220×90）、三个牌堆（80×80）、意图与血条挂敌人。
- 验收：写「锚点对照测试」，把实际节点矩形与 §1 表逐项比对（容差 ≤ 2px）。
- 不要做：不要改战斗逻辑。

### B5 · Run 骨架 + 15 层地图（关键路径）
- 目标：出现「标题 → 地图 → 连打三场 → 死亡 → 重来」的闭环。
- 产出：run.gd（纯逻辑可测：血量/金币/卡组/遗物/注剂/当前层/种子）；map_generator.gd 按原版规则生成 **7 列 × 15 行 + 6 条起始路径**，首层必战斗、第 9 层必宝箱、第 15 层必火堆、第 16 层 BOSS、连线不交叉、节点类型相邻约束；地图 UI（蓝图风，工程系冷青）。
- 验收：生成 1000 张地图，断言零非法连接、固定层正确、每层可达；截图。

### B6 · 房间：休整 / 商店 / 宝箱 / 事件
- 目标：路线上每个节点都能进。
- 产出：医疗舱（治疗/删卡）、补给舱（器官购物+删卡+注剂）、宝箱（遗物/金币）、异常讯号 ×8（含神印事件）。四界面互不重叠，可各自并行。
- 验收：每界面进出后 Run 状态正确；各一张截图。

### B7 · 奖励与结算
- 产出：reward_screen.gd（卡牌三选一、金币、注剂掉率）、game_over_screen.gd（血肉重塑演出）。
- 验收：奖励池取卡不重复、稀有度权重正确；截图。

### B8 · 内容量（原创）
- 目标：把「90% 还原」的内容密度补齐。
- 产出：卡 40+（攻击/技能/能力 + 状态牌 + 诅咒牌＝记忆碎片）、遗物 20、注剂 10、敌人 6+（含精英与 BOSS 意图模式表）。
- 硬性要求：**名称与描述全部原创**，效果数值对齐 B1 的对齐表；每张卡带 asset_id 指向卡面插图槽。
- 验收：schema 测试全绿；稀有度分布符合曲线；每条效果都有可测结算用例。

### B9 · 外壳
- 标题 / 教程（首战、首地图，复用 thought_bubble）/ 牌组查看 / 结算 / user:// 单槽存档。
- 验收：关掉游戏重开能续局。

### B10 · 核心区步行枢纽（可选，最后）
- TileMapLayer + 32×48 步行角色（脚部碰撞 16px、4px 网格吸附）、血肉重塑池、宋梅 NPC、下一层舱门。

## 5. 与上位计划的差异（本文件的修订）

| 上位计划 | 本文件 | 理由 |
|---|---|---|
| M0 像素地基放最前 | 拆成 B0（工具）与 B2（卡牌重制），B2 依赖 B1 | 工具与内容解耦，可并行 |
