# 《杀戮尖塔2》卡牌交互 / 队列 / 判定 —— 逆向笔记

> 来源：安卓版 APK 内的 `assets/.godot/mono/publish/arm64/sts2.dll`（未混淆，Godot 4 + C#，ILSpy 反编译）。
> 本文记录的是**机制、常量与时序**，用于对照实现；不含游戏源码文本。
> 注意：这是**《杀戮尖塔2》**的实现，与一代在交互细节上有差别（一代没有星费、没有选中卡牌独立容器等）。
> `assets/src/**/*.cs` 在包里只是 1 字节占位文件，真正逻辑必须从 sts2.dll 反编译。

## 1. 指向箭头（`NTargetingArrow`）

| 项 | 值 |
|---|---|
| 节点类型 | `Node2D` |
| 组成 | **19 个线段 Sprite2D + 1 个箭头头部** |
| 贴图 | `ui/combat/targeting_arrow_head.png`、`ui/combat/targeting_arrow_segment.png` |
| 线段缩放 | 从 **0.28 线性插值到 0.42**（第 i 段 = lerp(0.28, 0.42, i×2/19)），越靠近箭头越大 |
| 线段位置 | **二次贝塞尔曲线**采样，t = i/20，参数为（起点, 终点, 控制点） |
| 箭头头位置 | 目标点 + (0, 88) 按头部旋转 |
| 曲线终点 | 目标点 + (0, 40) 按头部旋转 |
| 头部旋转 | 控制点 → 目标点连线角度 + 90°（始终指向目标） |
| 线段旋转 | 与前一段连线切向 + 90°；第 0 段特判（按 y > 540 决定朝向） |

**控制点算法**（决定弧度形状）：
- X = 起点X − (头部X − 起点X) × 0.25
- 若起点 Y > 540（屏幕下半）→ Y = 头部Y + (头部Y − 起点Y) × 0.5
- 否则 → Y = 头部Y × 0.75 + 起点Y × 0.25

**手感关键点**
- 鼠标模式下**隐藏系统光标**（`Input.MouseMode = Hidden`），箭头即光标；结束/取消时恢复。
- 手柄模式下位置用 `Lerp(cur, target, delta × 14)` 平滑跟随，不是瞬移。
- 悬停高亮（`SetHighlightingOn(isEnemy)`）：箭头头从 **0.95 → 1.05**，时长 **1.0s**，缓动 **ELASTIC 出**；整体 modulate 切换为敌人色/友方色。取消高亮则瞬时回 0.95 + 白色。
- 调试开关 `NCombatUi.IsDebugHideTargetingUi` 可整体隐藏瞄准 UI。

**准星（`NSelectionReticle`）**
- 选中：alpha 0→1 用 **0.2s**；scale 0.9→1.0 用 **0.5s**，**EXPO 缓出**。
- 取消：alpha→0 用 **0.2s（SINE 出）**；scale 推到 **1.05**，0.2s——"涨一下再消失"。

## 2. 向上释放 / 出牌区判定（`NMouseCardPlay`）

### 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `_playZoneScreenProportion` | 0.75 | 出牌区基准线 = 屏幕高 × 0.75 |
| `_cancelZoneScreenProportion` | 0.95 | 取消区 = 屏幕高 × 0.95（最底 5%） |
| `_fakeLowerEnterPlayZoneDistance` | 100 | 起点在基准线**下方**时的拖拽距离 |
| `_fakeUpperEnterPlayZoneDistance` | 50 | 起点在基准线**上方**时的拖拽距离 |

### 阈值是"自适应"的，不是一条固定横线

```
基准 = 屏幕高 × 0.75
若用快捷键启动出牌      → 阈值 = 基准 + 100
若拖拽起点 Y > 基准      → 阈值 = max(基准, 起点Y − 100)
否则（起点在基准上方）   → 阈值 = min(基准, 起点Y − 50)
```

- 出牌区判定：**鼠标 Y < 阈值**
- 取消区判定：**鼠标 Y > 屏幕高 × 0.95**

**设计意图**：手牌贴底时必须拖足够远才触发（防误触）；手牌本来就高或牌少时不必拖那么远。

### 两种目标模式（`TargetMode`）

`None / ReleaseMouseToTarget / ClickMouseToTarget / Controller`

- 拖拽开始时左键**已按下** → `ReleaseMouseToTarget`（拖出松手即选中）
- 用快捷键启动 → `ClickMouseToTarget`（点一下进模式，再点目标确认）

### 流程

1. `StartCardDrag`：每帧把 holder 位置 **lerp 到鼠标**并等一帧，直到进入出牌区。
2. 进入后先做 `Card.CanPlay()` 判定；**不通过则取消**并可能冒"思考泡"说明原因。
3. 通过 → `CardHighlight.AnimFlash()`，进入选目标。
4. 单体目标 → 走 `NTargetManager.StartTargeting`；非单体（全体/自身等）→ `MultiCreatureTargeting`，只按"是否在出牌区"显隐多目标准星，等待松手/点击。
5. 松手后**再检查一次出牌区**，不在则取消（双重保险）。
6. `TryPlayCard(target)`。

### 取消途径
右键 / cancel 动作 / releaseCard 动作（Esc）/ 鼠标↔手柄切换 / **移动端在出牌区外松手**（`OS.HasFeature("mobile")`）。

### 拖拽期间的卡牌形态
- `CenterCard()`：位置移到屏幕水平中央、底部；**缩放固定 0.75**。
- 打出成功后，指向性卡牌的 holder 目标位置被设为"屏幕底部中央"。

## 3. 手牌悬停 / 抬起 / 选中动画

### 逐帧 Lerp，不用 Tween（可被打断）

| 属性 | 速率 | 吸附阈值 |
|---|---|---|
| 角度 | **10 /s** | < 0.1° |
| 缩放 | **8 /s** | < 0.002 |
| 位置 | **7 /s** | 距离² < 1 |

- 三者各有独立 CancellationToken：改目标即取消上一个协程，**支持连续打断**。
- **命中框防抖**：位置动画期间 hitbox 禁用，只有移动到位差 < **200px** 时才重新启用（`_reenableHitboxThreshold = 200`）。这是"牌还在飞时点不到"的原因。
- 悬停：ZIndex → 1，显示悬浮提示；离开时 tween 回 `SmallScale = 0.8`，**0.5s EXPO 缓出**。
- 选中：卡牌转入 `NSelectedHandCardContainer`（**先记录全局坐标**再重排，视觉上不跳），卡片 0.15s CUBIC 缓出移动到位。
- 选中容器排布：以第一张 holder 宽度为步长、整体水平居中；左右 FocusNeighbor 环回，供手柄导航。
- 拖拽开始 `BeginDrag()`：角度瞬时归 0、缩放瞬时设为 HoverScale。
- 取消拖拽 `CancelDrag()`：角度归 0、缩放回 1.0。
- 卡面 Flash（强化/关键字/费用变化触发）：alpha 0→0.6 用 0.15s，再 →0 用 0.3s。

### 手牌排布：硬编码查表（`HandPosHelper`）

**不是公式，是美术手调表**，1~10 张各有一套坐标和角度：

| 手牌数 | X 坐标 | Y 坐标 | 角度(°) |
|---|---|---|---|
| 5 | −340 / −170 / 0 / 170 / 340 | +10 / −30 / −50 / −30 / +10 | −8/−4/0/4/8 |
| 6 | ±460 / ±273 / ±90 | +13 / −25 / −50 | ±9/±6/±3 |
| 10 | ±610/±472/±340/±200/±64 | +38/+5/−21/−41/−50 | ±15/±12/±9/±6/±3 |

- 基础缩放 **0.8**；手牌 ≥8 张时再乘：8→0.95、9→0.9、10→0.85、11→0.8、12→0.75。
- 手牌上限 **10**（超出抛异常）。

## 4. 卡牌队列（`NCardPlayQueue`）

- 队列项 = `{ NCard 卡牌节点, GameAction 行动, Tween 当前补间 }`。
- **由行动队列事件驱动**：订阅 `RunManager.ActionQueueSet.ActionEnqueued`，每有一个 `PlayCardAction` 入队就生成一张"等待中的卡牌"。
- 本地打出：卡牌节点从手牌 holder **转交**给队列容器 → `MoveChild(card, 0)` → 从手牌移除 holder → tween 到队列位。
- 联机（他人打出）：在手牌意图位置附近创建一张 **0.25 缩放**的小卡牌入队。
- **队列位公式**：位置 = 打出堆目标位置 + 左移 `300 × ((i+1)/(i+3))`；缩放 = `0.8 × (1 − n/(n+1))`（n = i+1）。→ 越靠后的排队卡越小、越靠左。
- 补间：**0.35s，EASE_OUT + CUBIC**（位置/缩放/透明度同步）。
- 取消：**0.5s** 位置下移 30px + 淡出，然后释放节点；若该牌仍属于手牌堆则**回手**。
- 执行前 `UpdateCardBeforeExecution`：换入真实卡牌模型并刷新视觉 → `RemoveCardFromQueueForExecution`。
- 需要玩家选牌的卡：`ReAddCardAfterPlayerChoice`，若行动已在执行则直接动画进打出堆。

## 5. 打出判定（`CardModel.CanPlay`）

返回 `[Flags] UnplayableReason` 位掩码 + 阻止者模型：

| 位 | 名称 | 含义 |
|---|---|---|
| 2 | `HasUnplayableKeyword` | 带"不可打出"关键字 |
| 4 | `BlockedByHook` | 某 Hook（遗物/能力）禁止 |
| 8 | `BlockedByCardLogic` | 卡牌自身 `IsPlayable` 为假 |
| 0x10 | `EnergyCostTooHigh` | 能量不足 |
| 0x20 | `StarCostTooHigh` | 星费不足（二代新资源） |
| 0x40 | `NoLivingAllies` | 需要队友但没有存活队友 |

判定顺序：战斗状态是否存在 → Unplayable 关键字 → 资源是否足够 → 队友牌但场上只有自己 → `Hook.ShouldPlay` → `IsPlayable`。

- `CanPlayTargeting(target)` = `IsValidTarget(target) && CanPlay()`。
- `IsValidTarget`：AnyEnemy/AnyAlly 必须给目标；目标必须存活；再做阵营校验。
- **失败反馈不是简单灰掉**：
  - 能量不足且没看过教学 → 弹一次 FTUE 教学（打过 8 张牌后自动标记已完成，避免骚扰）。
  - 若原因有对应台词 → 在角色头顶冒一个**思考泡 VFX**（`NThoughtBubbleVfx`）说明为什么不能打。

### 高亮三态（`NCardHolder.UpdateCard`）

| 状态 | 条件 | 表现 |
|---|---|---|
| 可打出 | `CanPlay()` | `playableColor` 高亮 + `AnimShow` |
| 条件已激活 | `ShouldGlowGold` | **金色** |
| 特殊警示 | `ShouldGlowRed` | **红色** |
| 不可用 | 以上都不满足 | `AnimHide` |

## 6. 与《阿卡姆号》的对照落点

| 尖塔2 做法 | 阿卡姆号现状 | 建议 |
|---|---|---|
| 自适应出牌阈值（0.75/0.95 + 起点 ±100/50） | 无规范 | 直接采用，替换"固定横线" |
| 19 段贝塞尔箭头 + 隐藏光标 | 无 | 用 Line2D/精灵沿贝塞尔布点 |
| 逐帧 Lerp + 可打断 + 200px hitbox 防抖 | 卡牌交互未规范 | 优先做防抖，直接影响手感 |
| 手牌硬编码查表 | 手牌槽 455..1465 | 先按 5 张表落地，再扩到 8 |
| 队列由行动队列事件驱动 | 有能量/手牌管理 | 队列与逻辑结算解耦，动画排队播放 |
| 金光 = 条件激活 | 有"回响连击" | **金光直接映射"能接上回响"** |
| 失败冒思考泡说明原因 | 无 | 隔离值/神印可复用这套叙事反馈 |

## 8. 素材实测与特效配方（用于还原）

### 8.1 指向箭头贴图的真实尺寸

APK 里只发布了编译后的 `.ctex`（源 PNG 未打包），从 GST2 头部读出的原始像素：

| 贴图 | 原始尺寸 | 引擎缩放系数 | 实际包围盒 |
|---|---|---|---|
| `ui/combat/targeting_arrow_head.png` | **183 × 203** | 0.95 ~ 1.05 | 174 ~ 193 px |
| `ui/combat/targeting_arrow_segment.png` | **148 × 148** | 0.28 ~ 0.42 | 41 ~ 62 px |

**结论**：箭头不是"细线"，每个段有 41~62px 的块面。这是"看起来像不像"的关键 —— 把段做成细线会立刻失去原版的重量感。

### 8.2 特效场景的配方结构

| 原版场景 | 结构 | 参数要点 |
|---|---|---|
| `card_trail_<职业>.tscn` | 小卡影 + 拖尾贴图 + additive 星点 | 三档渐变淡出，按职业换色 |
| `card_sparkles_vfx.tscn` | 星形贴图 + additive | 盒形发射 120×170、spread 180°、重力 (0,−3)、**17 段 alpha 抖动**（闪烁感来源） |
| `hit_spark_vfx.tscn` | 长/短米粒速度线 + 碎屑 + 亮斑 + 外扩线条 | 白→HDR 白渐变；alpha 曲线斜率约 −2.9（极快熄灭） |
| `block_spark_vfx.tscn` | 同族 + 极坐标环 | 冰蓝白渐变 (0.75, 0.85, 1) → HDR 白 |
| `cards/exhaust_vfx.tscn` | 灰片 + 烟雾 | 暗色→白渐变，先扬后落的 alpha 曲线 |

### 8.3 本项目如何落地（重要）

**没有把原版贴图拷进项目**，原因有两条：

1. APK 里**只有编译后的 `.ctex`，没有源 PNG**，本来就不存在可直接使用的贴图文件；
2. 本项目目标是 Steam 抢先体验，把第三方商业素材放进发行版本会直接构成侵权风险。

因此做法是**还原配方、自绘素材**：特效参数（发射盒、速度、闪烁结构、熄灭节奏）照搬上述配方，颜色与形状换成项目自己的工程系冷青/洋红体系；箭头按实测比例（段 41~62px 的视觉重量）重新给基准值。

同时留了**贴图替换管线**：把 `targeting_arrow_head.png` / `targeting_arrow_segment.png` 放进 `assets/art/ui/`，箭头会自动切换到贴图模式，缩放系数与原版管线完全一致（段 ×0.28~0.42、头 ×0.95~1.05）。想换成任何自有或已授权美术资源，丢文件即可，不用改代码。
